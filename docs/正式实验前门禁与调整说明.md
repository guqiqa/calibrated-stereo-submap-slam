# 正式实验前门禁与调整说明

## 研究边界

主实验只比较相同双目前端、子地图定义、候选总预算和几何验证条件下的 C1、C4 与 P。
仿真真值仅用于路线控制和旁路评测，不得进入候选排序、可靠性估计或切换决策。

## 四道门

1. Gate A：构建、几何、候选配额、缺失证据和数值稳定性测试通过。
2. Gate B：6 个 pilot 布局的五类 query 可运行，C1/C4/P 数据连续且坐标尺度正常。
3. Gate C：逐帧场景 ID、合法集合、coverage、Top-1、几何验证和拒绝原因完整，校准模型冻结。
4. Gate D：仅在 A-C 通过后生成并冻结 full test 布局、路线、哈希、参数和运行顺序。

## 已完成调整

- 视觉节点支持场景 manifest、子地图真值、标签路径、ID 模式和校准模型参数。
- runtime 子地图与 `submaps.json` 的场景 ID 显式映射，关键帧按视觉估计位姿落入场景多边形。
- mapping route 以 `build` 模式生成带哈希的冻结地图数据库，query 只能以 `load` 模式读取且不改写。
- 候选按 visual/pose/topology 轮询去重，配额为 4/3/2，总预算为 10，并加入当前地图。
- 记录器使用旁路真值生成合法集合、coverage 和 Top-1 标签，不回写在线节点。
- 校准指标拆为 `q_top1` 对 Top-1 正确性、`q_cov` 对候选覆盖率。
- 新增两阶段校准：先拟合可靠性，加载后重跑 calibration，再拟合温度与 coverage 概率。
- pilot 批处理默认覆盖五类 query，并为每条路线创建独立目录和 manifest。
- 新增机器可读 preflight 报告，失败门禁止解释为正式可运行。

## 尚需运行验证

- 使用新接口重跑 6 布局 pilot，确认场景 ID、地图版本和状态日志连续。
- 用实际采帧结果检查 mapping/query 的 5 s、2 m、30 度间隔；waypoint 几何不能证明时间间隔。
- 基于 development/calibration pilot 跑通拟合，并用未参与拟合的 pilot 路线验证加载。
- 检查 P 的接受率和拒绝率，禁止仅以更低接受率换取表面错误率下降。
- Gate A-C 全部通过前，不生成或运行正式 test 集。
